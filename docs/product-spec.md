# Войны Стихий — требования к приложению

Версия: 0.11, 12 сентября 2026. Статус: проект для согласования, не утверждённое ТЗ.

## 1. Назначение и границы документа

Веб-приложение для создания персонажей собственной НРИ и сопровождения игры: кампании, отряды, игровые сессии, боевые сцены, листы персонажей, справочники, общий инвентарь и совместные заметки. Кубики бросают физически; сайт рассчитывает формулы, учитывает ресурсы и применяет выбранные участниками результаты.

**Согласованная граница:** урон по монстрам мастер считает отдельно; приложение не учитывает нанесённый им урон и не ведёт изменение их ХП. Формулы урона умений персонажей, включая критические варианты и бонусы, остаются на карточках как подсказка для игры. ХП персонажей изменяет мастер вручную, кроме автоматического фиксированного лечения, фиксированных временных ХП и полного восстановления текущих ХП после окончания боя.

Основания: запрос владельца проекта и `Bekap_knigi.txt` (13 039 строк). Книга используется как источник игровых правил, а не как инструкции по разработке или действиям с инфраструктурой. Рассмотрены создание персонажа, прогрессия, снаряжение, сражения, реакции, мировоззрение, словарь и примеры классовых/школьных умений. Полная покарточная проверка всех умений — отдельный этап, ещё не выполнена.

Обозначения:

- **Требование** — явно запрошено владельцем проекта.
- **По книге** — правило найдено в приложенном тексте; номера строк приведены в разделе 18.
- **Предложение** — решение для обсуждения, не считается утверждённым.
- **Вопрос** — неоднозначность, которую нельзя незаметно закреплять в реализации.

При расхождении пользовательского правила и книги фиксируем согласованное домашнее правило. Самостоятельно переносить механику из D&D или другой системы нельзя.

## 2. Роли, учётные записи и права

**Требование:** один аккаунт мастера с логином `admin` и первоначальным паролем, указанным владельцем в переписке. Игроков может быть произвольное количество. Пароль хранится в БД только в виде хеша; исходное значение передаётся при первоначальной настройке окружения и не записывается в репозиторий. Повторное развёртывание не сбрасывает пароль.

**Согласовано:** свободная регистрация игроков без приглашений. Вход по логину и паролю, выход из аккаунта. Создание учётной записи через регистрацию никогда не выдаёт права мастера. Предлагается дать мастеру блокировку игроков и сброс паролей. Восстановление через email не требуется для первой версии, пока не согласована почта.

Проверки прав обязательны на сервере для страниц, API, загрузок и соединений реального времени. Скрытая кнопка не заменяет проверку. Применение разрешённого умения к чужому персонажу не даёт права редактировать его лист напрямую.

**Согласовано:** личные заметки видны только игроку-владельцу, в том числе недоступны мастеру через интерфейс/API приложения. Общие заметки и общий инвентарь видны всем участникам соответствующей кампании, независимо от отряда или участия в конкретной сессии. Это не глобальная публикация для всех зарегистрированных игроков.

**Оставшиеся вопросы:** чужие персонажи видны глобально или только в общих кампаниях; видимость содержимого личной сумки. Пока глобальный просмотр листов соответствует буквальному запросу. Приватные заметки исключаются из чужих листов и ответов API независимо от доступности остального листа.

## 3. Кампания, отряд, сессия, сцена

Используем термин «кампания» для длительной общей истории.

**Согласовано:** игроку доступен список кампаний с действием «Вступить». Он самостоятельно выбирает, какие его персонажи входят в кампанию, добавляет и убирает их из кампаний, выбирает и меняет их отряд либо оставляет в общем пуле. Подтверждение мастера для этих операций не требуется. Чужих персонажей игрок перемещать не может. Членство в нескольких кампаниях сохраняется: вступление в новую не удаляет остальные связи автоматически.

Перемещение между кампаниями/отрядами не дублирует персонажа и его инвентарь, не восстанавливает ХП и ресурсы и не завершает бой. Предложение для активной сцены: изменение организационного состава не меняет её уже зафиксированный состав; участие в текущем бою завершается отдельной операцией. Создание кампаний и отрядов остаётся функцией мастера, пока не согласовано иное.

| Сущность | Значение и связи |
|---|---|
| Игрок | Владеет любым количеством персонажей |
| Персонаж | Один постоянный лист, один владелец, участие в одной или нескольких кампаниях |
| Кампания | Общий контекст, список персонажей, отряды, пул персонажей без отряда |
| Участие в кампании | Связь персонажа с кампанией и его назначение в отряд внутри неё |
| Отряд | Группа персонажей одной кампании |
| Игровая сессия | Создаваемая мастером игровая встреча с выбранными персонажами, общими заметками и инвентарём |
| Боевая сцена | Конкретный бой отряда в рамках сессии, с участниками, инициативой, ходами и журналом |
| Участник сцены | Персонаж или, если согласовано, управляемое мастером существо; хранит состояние боя |

**Предложение:** персонаж входит максимум в один отряд внутри одной кампании; отсутствие назначения означает общий пул. В другой кампании у него может быть другое назначение. Состав сессии и начальный состав сцены сохраняются отдельно от текущего состава отряда: перемещение персонажа между отрядами не переписывает историю боя.

**Согласовано:** состояние персонажа едино между кампаниями: характеристики, уровень, умения, ХП и личный инвентарь не имеют отдельных версий по кампании. **Предложение:** один персонаж участвует максимум в одной активной боевой сцене одновременно.

Сессия имеет состояния «Подготовка», «Идёт», «Завершена», сохраняется после окончания и может содержать несколько последовательных боёв. Общие записи и предметы не исчезают при окончании боя. Нужно согласовать перенос общего имущества между сессиями: предлагается постоянное имущество отряда, доступное на странице сессии, и отдельные заметки каждой встречи.

## 4. Лист персонажа

### 4.1. Основные сведения

Имя, фотография, раса и подраса, класс, уровень, предыстория, ремесло, мировоззрение, специализации, основная и дополнительная школы. В общем списке мастер всегда видит владельца. Фотографию можно загрузить, заменить и удалить; приложение проверяет формат и размер и создаёт уменьшенную копию.

По книге мировоззрение включает три выбора из пар «Личное / Общее», «Свобода / Необходимость», «Хаос / Порядок», необязательный четвёртый элемент, два приоритета и выбор одного активного и одного пассивного умения. Специализаций может быть несколько: одиночного поля недостаточно.

### 4.2. Характеристики и вычисления

- Шесть базовых характеристик: Сила, Ловкость, Телосложение, Интеллект, Мудрость, Харизма.
- Для каждой: исходное значение, постоянные прибавки, временные изменения, итог и модификатор.
- Сумма шести характеристик: отдельно базовая и текущая, если временные эффекты изменяют сумму.
- Максимальные, текущие и временные ХП — разные величины.
- КД, скорость, инициатива, доступное число реакций, навыки и специализации.
- При необходимости из правил: размер, владения оружием/доспехами, досягаемость, сопротивления, уязвимости, агро, дополнительные классовые ресурсы.

По нажатию на число открывается расчёт: база → источники бонусов → ограничения → итог. Условные бонусы показываются с условием и не прибавляются безусловно: например, бонус к атакам мечом не меняет все атаки персонажа.

Правила, найденные в книге:

- КД: `5 + модификатор Ловкости + min(5, сумма бонусов брони и щита)`, с отдельным учётом иных применимых эффектов. Порядок отдельных штрафов и ограничений требует согласования.
- Владение навыком: +2; подходящая специализация: +3. Применимость специализации выбирается для конкретной проверки.
- ХП зависят от класса: например, у Адаптирующегося бойца на первом уровне `18 + значение Телосложения`, далее `4 + модификатор Телосложения` за уровень.
- Скорость определяется расой и изменяется эффектами и снаряжением.
- Временные ХП поглощают урон первыми. Согласовано: действуют до конца боя или полного расходования и не складываются. При начислении используется `max(текущий остаток временных ХП, новое начисление)`, а не сумма и не исторический максимум. Например: осталось 3, начислено 5 → становится 5; осталось 7, начислено 5 → остаётся 7. Более слабые начисления не хранятся как запас на будущее.

**Согласовано:** модификатор равен `floor((характеристика − 10) / 2)` — округление вниз, в том числе для отрицательных значений. Примеры: 9 → −1, 10 → 0, 13 → +1, 16 → +3.

**Актуальное решение:** игрок свободно редактирует базовые характеристики своего персонажа в любой момент, без привязки к повышению уровня и без разрешения мастера. Мастер также может менять их в любой момент. Временные эффекты и экипировка продолжают изменять итоговые значения автоматически. Это решение заменяет ранее согласованные ограничения редактирования по уровням.

**Справочное правило развития:** на уровнях 3, 5, 7 и 9 повышаются две разные характеристики на +1 каждую. Приложение не принуждает к этому правилу, не блокирует ввод и не выдаёт повышения автоматически; игрок сам изменяет значения. **Осталось уточнить:** округление остальных дробей и пересчёт максимальных ХП после изменения Телосложения. Проверяется корректность числового ввода, а не соответствие развития персонажа книге.

Модификатор школьного умения берётся от характеристики, указанной в определении школы. Классовые умения используют модификатор основной школы персонажа. Модификатор оружия определяется соответствующей оружейной школой. Для оружия с несколькими школами правило выбора между ними ещё требуется уточнить; конкретное указание в описании умения учитывается отдельно.

**Предложение:** при изменении максимума текущие ХП не лечатся автоматически; превышение нового максимума отправляется мастеру на разрешение. Игрок не может обойти запрет изменения текущих ХП сменой класса или уровня.

### 4.3. Создание и развитие

Пошаговая форма: сведения → раса/подраса → класс и школы → характеристики → предыстория/мировоззрение → умения и небоевой путь → снаряжение → проверка листа.

Нужны ручной ввод физических бросков и подсказки о незаполненных полях. Доступные по книге варианты можно подсвечивать или фильтровать по желанию игрока, но правила создания и развития не блокируют самостоятельное редактирование листа. По книге есть очко причуд и выбор между ремеслом, школьными небоевыми умениями и альтернативными специализациями; они отображаются как справочная помощь.

Игрок свободно редактирует сведения своего персонажа: характеристики, уровень, класс, школы, набор изученных умений, навыки, специализации, экипировку и прочие поля листа. Одобрение мастера для отклонений от правил развития не требуется. Сохраняются отдельные правила доступа к текущим/временным ХП, чужим персонажам и общему справочнику, а также правила применения действий в бою.

Изменение уровня — обычное редактирование поля. Отдельного шага распределения характеристик, обязательного выбора умений, выдачи очков и автоматических прибавок нет. Зависимые показатели продолжают рассчитываться из текущих данных листа. Изменения сохраняются в истории. Редактирование набора изученных умений означает добавление, удаление и замену умений у персонажа; определения общих умений и их механики по-прежнему редактирует мастер в справочнике.

## 5. Умения и справочники

### 5.1. Карточка умения

Название, описание, источник (класс, школа, раса, предыстория, мировоззрение, предмет), категория, круг, требования, стоимость действия, цели и дальность, формулы попадания/урона/лечения, ключевые слова, эффекты, варианты результата и правила восстановления использований.

Боевые активные, боевые пассивные и небоевые умения показываются раздельно. У пассивного умения могут быть активируемые части: например, пассивная «Смена облика» разрешает изменить оружие малым действием. Одного флага «пассивное» недостаточно для описания механики.

У изученного умения сохраняются источник получения, версия определения, максимальные и оставшиеся применения. Согласовано: таблица применений задаёт отдельный запас каждому умению, а не общий пул круга. Дополнительные классовые ресурсы учитываются отдельно, если предусмотрены конкретной механикой. Карточка показывает полный текст, ключевые слова с объяснением, актуальную формулу, стоимость, остаток и причину недоступности.

**Согласовано:** небоевые умения нельзя применять в бою. У них нет расходуемых применений: использование требует времени, указанного в описании. На карточке показывается время выполнения, а не счётчик зарядов. Это авторское правило имеет приоритет над встречающимися в книге ограничениями «раз за сцену» для небоевых умений.

### 5.1.1. Критический урон

Согласованные числовые примеры определяют расчёт: обычный крит удваивает исходный набор кубиков. Каждый дополнительный «Крит 1» добавляет ещё один исходный набор, а не удваивает уже увеличенное число. Для исходного набора D и суммарного дополнительного значения K: критический набор равен `(2 + K) × D`. Отдельные расовые добавки применяются сверх него; орк добавляет 1Ор к критическому урону оружием, как указано в книге. Ор означает полный набор кубиков урона используемого оружия.

| Атака кинжалом 1к4 | Обычный урон | Крит |
|---|---|---|
| Стандартная атака | 1к4 | 2к4 |
| Стандартная атака, оружие Крит 1 | 1к4 | 3к4 |
| Умение 2Ор | 2к4 | 4к4 |
| Умение 2Ор, оружие Крит 1 | 2к4 | 6к4 |
| Умение 2Ор, оружие Крит 1, персонаж орк | 2к4 | 7к4 |

Таблица фиксирует только кубики. Предложение: постоянные прибавки, включая Мод, при крите не умножаются. Это, порог критического попадания и критический провал ещё требуют уточнения. Alt показывает рассчитанный критический набор кубиков с отдельными бонусами.

### 5.2. Ключевые слова и правила

Мастер создаёт и редактирует ключевые слова, их описания и параметры: например, `Дальнобойный 5`, `Крит 1`, тип оружия или стихию. Одно слово может иметь числовой параметр. Переименование не должно разрушать ссылки.

Бонус задаётся структурированно: источник, цель изменения, величина/формула, условия по словам умения и оружия, длительность, правило сложения. Например: «+1 к урону умениями с ключевым словом Огонь». При изменении слов доступность и формулы пересчитываются.

Не всё жирное в книге автоматически является ключевым словом: при импорте различаем действие, дальность, эффект, тип урона и ссылку на другое умение. «Реакция» как действие и стихийная реакция — разные понятия.

### 5.3. Списки

Полные страницы с поиском, фильтрами, сортировкой и пагинацией для умений, снаряжения, эффектов, ключевых слов, рас/подрас, классов, школ, предысторий, мировоззрений/приоритетов, ремёсел/рецептов, навыков и специализаций. Для персонажей — фильтры по владельцу, кампании, отряду, классу и уровню.

Фильтры умений: источник, круг, категория, тип действия, ключевые слова, тип урона и доступность выбранному персонажу. Для предметов: тип, слот, оружейные слова, требования, свойства. Поиск сохраняется при возврате из карточки.

Мастер может добавлять, редактировать и удалять записи. **Предложение:** используемые записи архивируются, чтобы не ломать существующих персонажей. Правка справочника создаёт версию; мастер видит затронутые листы и выбирает миграцию. Активный бой не меняется незаметно после правки определения.

## 6. Инвентарь

Разделы листа: «Надето» и «С собой». Экземпляр предмета хранит шаблон, название, количество, свойства, улучшения/зачарования, состояние и владельца/место хранения. Индивидуально улучшенное оружие не изменяет базовый шаблон у всех игроков.

Экипировка учитывает слоты, занятые руки, щит, хват универсального оружия, владения и требования. После надевания/снятия пересчитываются КД, доступность умений и условные бонусы. Изменение экипировки в бою учитывает стоимость действия по правилам. Хранение предмета в сумке само по себе не даёт бонуса надетого предмета.

Общий инвентарь показывает предметы группы, количество и историю перемещений. Передача в личный инвентарь и обратно — одна операция: предмет не дублируется при одновременных действиях двух игроков. Права на расходование общих вещей и необходимость подтверждения передачи нужно согласовать.

Полная автоматизация крафта не следует автоматически из наличия поля «ремесло»: рецепты, материалы и создаваемые предметы входят в справочник, а учёт времени/производства согласуется отдельно.

## 7. Боевая сцена

### 7.1. Подготовка

Мастер выбирает сессию и отряд, подтверждает участников, запускает сцену. Инициатива вводится по физическим броскам. По книге игроки распределяют общий пул результатов 2к6 и затем добавляют модификатор Ловкости и прочие бонусы. Предлагается дать ввод пула и назначение результатов персонажам, а также ручную расстановку мастером. Разрешение равной инициативы — открытый вопрос.

Урон по монстрам и изменение их ХП не ведутся в приложении. Противники также не включаются в очередь ходов. Для атаки по внешнему противнику достаточно учесть применение умения и его ресурсы; карточка монстра и ввод нанесённого ему урона не требуются. Призывы, тотемы, иллюзии и скакуны остаются отдельным вопросом объёма реализации.

### 7.2. Действия и доступность

**По книге:** основное (оно же стандартное), движение и малое действие на ход; основное можно обменять на движение или малое. Реакций на раунд — `max(1, модификатор Мудрости)` с учётом бонусов. В отдельных умениях встречаются свободные действия.

**Уточнённое требование пользователя:** после применения умения тускнеют те умения, для которых больше нет ресурса действия.

**Согласовано 12 сентября:** отдельный учёт ресурсов действий по книге. Расход основного действия не блокирует оставшееся малое, движение, разрешённую реакцию и свободное действие. Свободное действие не расходует эти три ресурса, но соблюдает ограничения собственного умения и условия срабатывания.

Блокировки: чужой ход, закончились использования, нет подходящего оружия, состояние запрещает действие, нет нужного ресурса или цели. Сервер проверяет их повторно при подтверждении. Реакции доступны вне своего хода только по согласованному триггеру.

### 7.3. Применение умения

1. Игрок открывает умение своего персонажа.
2. Видит формулы с текущими бонусами, стоимость и остаток использований.
3. Выбирает цель или несколько целей из допустимых участников; союзники показаны с именами и фотографиями.
4. При необходимости выбирает оружие, режим, условные бонусы и вариант применения.
5. Бросает кубики физически и вводит результат либо выбирает исход: попадание, промах, критическое попадание/провал, вариант случайного эффекта. Несколько целей могут иметь разные исходы.
6. Видит предварительный итог: расход ресурсов, эффекты, автоматическое фиксированное лечение/временные ХП и подсказки для ручного изменения ХП мастером. Урон по монстрам не вводится и не записывается системой.
7. Подтверждает; сервер атомарно записывает событие, ресурсы и последствия, затем обновляет экраны участников.

Закрытие окна до подтверждения ничего не расходует. Повторное нажатие или повтор запроса после потери связи не создаёт второе применение. Для `Надёжного` умения промах не расходует применение; отдельный вопрос — расход самого действия и частичное попадание по нескольким целям.

Если результат определяется кубиком, интерфейс всегда позволяет внести физический результат или выбрать предусмотренную правилами ветку. Никакого обязательного встроенного генератора случайных чисел. Ручная нестандартная правка мастера отмечается в журнале отдельно.

### 7.4. Ход, раунд и завершение

«Следующий ход» завершает ход текущего участника и передаёт его следующему по инициативе. Когда сходили все персонажи, начинается новый раунд. Согласовано: мастер начинает бой, игроки завершают ход своих персонажей. Противники не участвуют в очереди приложения; их действия мастер ведёт отдельно. Возможность мастера принудительно переключать чужой ход остаётся предложением. Это не личная кнопка неограниченного восстановления действий.

Порядок событий должен быть един: завершение хода → эффекты конца хода → истечения → переход → новый раунд при необходимости → обновление ресурсов по их правилам → начало хода → эффекты начала хода. Для каждой длительности хранится точная граница; окончательный порядок утверждается вместе с правилами длительности.

«Закончить сцену» завершает бой, сохраняет журнал и восстанавливает запас применений каждого боевого умения. Перед действием показывается подтверждение. Небоевые умения не имеют расходуемых применений, поэтому сброс для них не нужен.

**Согласовано:** при окончании боевой сессии все текущие ХП персонажей-участников автоматически восстанавливаются до максимума. В этом документе «окончание боевой сессии» трактуется как действие «Закончить сцену» для конкретного боя; завершать всю игровую встречу не требуется. Это отдельное исключение из ручного изменения ХП мастером.

Предложение по порядку: снять эффекты, истекающие при завершении боя, пересчитать максимальные ХП и восстановить текущие до полученного максимума. Согласовано: оставшиеся временные ХП при завершении боя обнуляются. Предметы не восстанавливаются. Долгосрочные эффекты обрабатываются по своим правилам. Отмена завершения возвращает прежние текущие и временные ХП вместе с остальным состоянием сцены.

## 8. Эффекты, бонусы и пример «Благословения»

Экземпляр эффекта: определение и версия, источник, цель, сила, параметры, начало, длительность и точный момент окончания, условия действия, правило повторного наложения, ссылка на породившее событие.

Сроки должны поддерживать: N ходов цели, N ходов источника, N раундов, до конца текущего/следующего хода указанного участника, до конца боя, до отдыха, постоянный, до ручного снятия. Уменьшать все эффекты на каждом чужом ходу нельзя.

По книге обычный эффект длится три хода, если не указано иное; при одинаковых эффектах разной силы остаётся сильнейший. Согласовано: длительность считается по ходам цели; повторное наложение обновляет срок. Эффект действует непрерывно, в том числе между ходами цели и во время её реакций, и снимается после завершения последнего положенного хода цели. Явные сроки из текста умения, например «до конца следующего хода источника», сохраняют свой смысл.

Пример эффекта на три хода, наложенного до начала хода танка: наложение → промежуток до хода танка → первый ход целиком → промежуток с доступными реакциями → второй ход целиком → промежуток с доступными реакциями → третий ход целиком → снятие сразу после завершения третьего хода. Остаток уменьшается на границе конца хода цели: 3 → 2 → 1 → снят; на чужих ходах и в начале хода цели он не уменьшается. Повторное наложение возвращает полный срок.

Частный случай наложения эффекта посреди уже начавшегося хода самой цели пока требует уточнения: считать ли этот неполный ход первым. Пример владельца однозначно определяет поведение при наложении до начала хода цели.

Есть исключения: Оглушение суммируется, Насыщение усиливает и продлевает эффект, противоположные первородные эффекты нейтрализуются, некоторые сочетания образуют новый эффект. Согласовано: при нескольких подходящих стихийных реакциях вариант выбирает тот, кто накладывает вступающий в реакцию эффект. Выбор показывается до подтверждения и сохраняется в событии для отмены/повтора. Исчезновение исходных эффектов при созидательной реакции ещё требует уточнения.

**Умение «Благословение», школа Света, 1 круг** (строки 8133–8139): цель получает «Благословение 2», 5 временных ХП и +1 к урону до конца боя. Сам **эффект «Благословение X»** даёт +X к попаданию. Это три самостоятельных последствия одного применения.

Сценарий интерфейса: выбрать умение → выбрать союзника → увидеть три последствия → подтвердить. У союзника появляется источник +2 к попаданию, источник +1 к урону и соответствующее изменение временных ХП по согласованной политике. Пример корректного отображения: «Попадание: база + 2 (Благословение от персонажа А)», «Урон: формула + 1 (умение Благословение)».

**Согласовано:** фраза «до конца боя» в описании умения относится только к +1 урона. Эффект «Благословение 2» (+2 к попаданию) действует стандартные три хода. Эти два бонуса имеют независимые сроки: после истечения бонуса попадания бонус урона остаётся до завершения боя. Начисленные 5 временных ХП действуют до полного расходования или конца боя по общему правилу временных ХП, не складываясь с уже имеющимися.

**Согласовано:** игрок — владелец ауры — сам указывает, на кого она распространяется, и меняет список получателей по ходу игры. Для других умений и эффектов с выбором целей, включая конусы и линии, цели аналогично выбирает владелец источника. Мастер сохраняет возможность корректировки.

В карточке ауры доступно действие «Выбрать получателей» с множественным выбором участников. После подтверждения сервер применяет эффекты к добавленным получателям и снимает вклад этой ауры с исключённых, пересчитывая листы и обновляя их в реальном времени. Бонусы от других источников при этом сохраняются. Изменение получателей действующей ауры само по себе не является повторным применением умения и не расходует его использования или действия, если отдельное правило умения не требует иного.

Сайт проверяет допустимый состав и тип целей по умению; нахождение в радиусе ауры или области действия определяет игрок. Автоматического определения расстояний, входа и выхода из области не требуется. Выбор получателей чужого эффекта не даёт права редактировать их листы напрямую.

Условные и случайные механики оформляются выбором в окне применения. Например, «Цветной поток» предлагает цвет/результат к6 и связанные последствия; выбранный исход сохраняется для отмены и повтора.

## 9. ХП и экран мастера

**Требование:** текущие ХП редактирует только мастер, максимум берётся из расчёта листа. Нужны две отдельные страницы:

- Управление: список активных персонажей, владелец, текущее/максимальное значение, временные ХП, ввод точного значения, нанесение урона и лечение.
- Экран показа: крупные карточки и полосы ХП выбранных активных персонажей; обновление без перезагрузки, без элементов редактирования. Полноэкранный режим.

Изменение подтверждается сервером и синхронизируется в листах, управлении и на экране показа. При разрыве связи виден индикатор устаревших данных; после подключения загружается актуальное состояние.

**Согласовано 12 сентября:** все изменения ХП персонажей мастер вносит вручную, кроме фиксированного лечения и фиксированных временных ХП от умения — они применяются автоматически. Если лечение или временные ХП зависят от броска кубика, мастер меняет их вручную по физическому результату. Урон персонажам, включая периодический, не списывается автоматически. Игрок не получает прямого доступа к редактированию ХП. Поэтому 5 временных ХП от «Благословения» применяются автоматически.

**Дополнение:** окончание боя автоматически восстанавливает текущие ХП всех персонажей-участников до максимума. Это не ручное редактирование игроком; восстановление является частью единого события завершения сцены и синхронизируется со всеми экранами.

Урон по монстрам мастер считает отдельно: приложение не рассчитывает фактический урон по конкретному монстру, не списывает и не хранит его ХП. Отображение формул урона и бонусов на карточках персонажей сохраняется.

**Согласовано:** лечение и временные ХП, вычисляемые из модификатора даже без кубиков, не считаются фиксированными и вносятся мастером вручную. Автоматическое применение относится к явно заданному фиксированному числу, например 5 временных ХП.

Для лечения и временных ХП с броском или зависимостью от модификатора интерфейс показывает формулу и пометку «ХП изменяет мастер». Предлагается связать ручное изменение мастером с исходным умением для журнала и отмены. Пока мастер не ввёл результат, интерфейс не показывает лечение как выполненное. Для периодических изменений с ручным вводом нужен список напоминаний на границе хода.

**Согласовано:** текущие ХП не могут быть отрицательными, лечение ограничено максимумом ХП. Ограничения действуют и на ввод мастера, и на автоматическое фиксированное лечение. Временные ХП учитываются отдельно. Механика смерти/потери сознания при нуле ещё требует уточнения. На экране цвет дополняется числом и подписью, чтобы состояние не зависело только от восприятия цвета.

## 10. Отмена и повтор отменённого

**Требование:** отменить действие и вернуть отменённое. Под действием здесь понимается подтверждённая игровая операция, а не только ресурс «основное действие».

В журнале сохраняются автор, время, исходные параметры, физические результаты, затронутые цели, изменения ресурсов/эффектов/ХП и причинные связи. Отмена умения восстанавливает потраченное действие, использование и все его последствия; повтор применяет тот же сохранённый результат без нового броска.

**Согласовано:** игрок отменяет своё последнее действие, мастер — своё последнее. Это отдельная история отмены для каждого автора, а не право мастера отменять чужие события. Независимые более поздние действия других участников сохраняются. Повтор возвращает собственное отменённое действие с прежними параметрами.

**Предложение для зависимостей:** если чужое последующее действие использовало результат отменяемого, откат блокируется с объяснением зависимости; владельцы сначала отменяют зависимые действия. Чужие изменения нельзя молча откатить или затереть снимком старого состояния. Ручное изменение ХП мастером остаётся его действием, даже если связано с умением игрока. Новое собственное действие после отмены закрывает обычный повтор своей отменённой ветки; независимое чужое действие само по себе её не закрывает. Эту политику конфликтов ещё требуется подтвердить.

Переход хода/раунда — тоже событие, включая истечения и периодические последствия. Окончание сцены можно отменить мастеру только пока нет последующих зависимых операций или нового боя; иначе нужен явный согласованный сценарий восстановления.

Общие заметки имеют собственную историю и отмену текста. Они не откатываются кнопкой отмены боевого действия. Редактирование листа и справочника также не смешивается с боевым журналом.

## 11. Страница сессии и совместная работа

Страница показывает название, кампанию, отряд, статус, состав союзников, ссылки на листы, текущую сцену, общий инвентарь и заметки. Игрок видит участников своей сессии и их изменения в реальном времени.

Заметки редактируются одновременно несколькими участниками: изменения текста объединяются, а не заменяются последним сохранением целого поля. Нужны индикатор сохранения, присутствие участников, восстановление связи и история версий. Критерий: два человека одновременно редактируют разные части текста, обе правки сохраняются после перезагрузки.

**Предложение:** ограниченный редактор с заголовками, абзацами, списками и ссылками. Изображения, сложные таблицы и полноценный аналог всех функций Google Docs не обязательны. При отключении сети сохраняется локальный черновик текста; игровые команды не выполняются незаметно из очереди после восстановления сети.

Личные заметки персонажа — отдельное поле, доступное только игроку-владельцу. Общие заметки и общий инвентарь видны всем участникам кампании. Права редактирования общих данных вне своей сессии остаются на уточнении. Приватный текст не включается в общие документы, журнал боя или данные чужого просмотра листа.

## 12. UI/UX

Приоритетные устройства — ноутбуки и телефоны. Подробное расположение кнопок, адаптация экранов и сценарии проверки описаны в [ui-ux.md](ui-ux.md). При различиях с общей схемой ниже актуальным предложением считается этот отдельный документ: две постоянные колонки на ноутбуке, одна на телефоне; союзники и журнал раскрываются по необходимости. Референс Google Таблиц предоставлен владельцем, но пока требует авторизации и визуально не проверен.

### 12.1. Рабочий экран

**Предложение:** компактный настольный интерфейс с постоянной верхней навигацией «Персонажи / Кампании / Сессии / Справочники», переключателем активной кампании и вкладками открытых персонажей. У мастера добавляется «Управление». Переключение сохраняет выбранный раздел и позицию списка.

Лист на широком экране:

| Область | Содержимое |
|---|---|
| Верхняя строка | Фото, имя, класс/уровень, кампания/отряд, владелец при необходимости |
| Левая компактная колонка | Шесть характеристик, модификаторы, сумма, ХП, КД, скорость |
| Центральная область | Вкладки «Бой», «Умения», «Инвентарь», «История и заметки» |
| Правая панель в бою | Союзники, эффекты, журнал последних событий |
| Нижняя закреплённая панель боя | Раунд, чей ход, оставшиеся действия, следующий ход, отмена/повтор |

Вкладка «Бой» показывает активируемые умения, эффекты и ресурсы. Полное описание открывается в боковой панели, применение — в компактном диалоге с выбором целей. Основные числа и управление боем остаются видимыми.

«На одном экране» означает отсутствие необходимости уходить со страницы ради основного игрового цикла, а не попытку уместить все описания и предметы сразу. Предлагаемая контрольная ширина — 1440×900; на 1366×768 допускается внутренний скролл списка умений. На телефоне — одна колонка с закреплёнными ХП и кнопкой действий.

### 12.2. Визуальные состояния и удобство

- Доступные умения, недоступные с причиной, постоянные пассивные эффекты и ожидающие подтверждения выглядят различимо.
- Умения остаются читаемыми в тусклом состоянии; описание можно открыть всегда.
- Активные бонусы имеют источник, величину и оставшийся срок.
- При удержании Alt карточки урона показывают критический вариант; отпускание и потеря фокуса возвращают обычный. Есть кнопка «Крит» для телефона и клавиатур без удобного Alt.
- Критический вариант — формула/диапазон с пояснением, а не придуманное точное число физического броска. Точное значение можно показать после ввода результатов. Кубики рассчитываются по согласованным примерам раздела 5.1.1; правило постоянных прибавок пока уточняется.
- Выбор цели показывает имя персонажа, владельца, ХП и уже активный аналогичный эффект.
- Двойные подтверждения не нужны для обычного просмотра и редактирования; завершение сцены и удаление требуют явного подтверждения.
- Все основные функции доступны с клавиатуры; различия не обозначаются одним только цветом.

Цвета, декоративный стиль и окончательные макеты согласуются отдельным визуальным прототипом после принятия функциональных решений.

## 13. Техническая структура

**Требование:** сервер на Python/Django, БД PostgreSQL. Репозиторий `BrudLord/VoiNaTitii`; разработка ведётся в репозитории, развёртывание — на подготовленной ВМ `84.201.155.77`, пользователь `budimir`, каталог `/home/budimir/VoiNaTitii`.

**Предложение:** единое приложение Django с модулями accounts, characters, rulebook, campaigns, sessions, combat, inventory и collaboration. PostgreSQL — постоянный источник данных. Вычисления правил и проверка команд находятся на сервере, чтобы разные вкладки не расходились в игровых результатах.

Страницы Django и интерактивные клиентские компоненты для листа, боевого окна и редактора; WebSocket для доставки обновлений. Совместный текст требует алгоритма слияния операций (CRDT или OT), а не одной рассылки целого документа. Конкретную библиотеку редактора, транспорт и способ фоновых задач выбираем при техническом проектировании.

Рекомендуемые группы данных:

| Группа | Основные сущности |
|---|---|
| Доступ | Учётная запись, роль, сессия входа |
| Персонажи | Персонаж, значения характеристик, выборы развития, владения, изученные умения |
| Справочник | Версия правил, класс, раса/подраса, школа, умение, ключевое слово, эффект, предмет, рецепт |
| Организация игры | Кампания, участие, отряд, сессия, состав сессии |
| Бой | Сцена, участник, порядок ходов, ресурс, эффект, событие, запрос изменения ХП |
| Предметы | Экземпляр предмета, контейнер/слот, перемещение |
| Совместная работа | Документ заметок, операции/снимки, история |

Связи, владельцы и права хранятся явными полями/таблицами. Структурированные параметры эффектов могут допускать расширения, но не заменяют всю модель одним произвольным JSON. Формулы используют ограниченный набор операций и переменных, без выполнения произвольного Python из редактора мастера.

Изменения сцены выполняются транзакционно с контролем версии. Одновременные несовместимые команды не перезаписывают друг друга; клиент получает актуальное состояние и понятное сообщение. Событие отправляется клиентам после фиксации в БД. У команды есть идентификатор для защиты от повторного исполнения.

## 14. Перенос книги в систему

1. Сохранить исходный текст в репозитории как версионируемый источник правил; внешние иллюстрации не загружать автоматически как обязательную часть приложения.
2. Извлечь главы, классы, школы, умения, предметы и таблицы, сохраняя исходный текст и ссылки на строки.
3. Нормализовать имена и ключевые слова, не меняя смысл правил.
4. Создать структурированные формулы, условия, эффекты, ресурсы и длительности.
5. Сформировать отчёт: что распознано, что требует решения, где совпали названия, что осталось только описанием.
6. Проверить каждую карточку, включённую в автоматизацию; опубликовать версию справочника.

Есть признаки неоднородности источника: например, «Кавалерист» присутствует в тексте, но не в показанном оглавлении; разные записи слова «Надёжный» и вариантов дальности требуют нормализации. Оглавление не используем как единственный перечень контента.

Карточки со сложной неавтоматизированной механикой видны с честной пометкой и ручным выбором мастера. Их нельзя считать полностью реализованными только потому, что описание импортировано. Итоговый объём автоматизации принимается по реестру карточек и механик.

## 15. Развёртывание и эксплуатация

Предлагаемый процесс: изменения в репозитории → проверка → фиксация версии → доставка на ВМ → миграции → запуск → проверка доступности. Боевые данные не хранятся в Git. Ключи, пароли и настройки окружения находятся вне репозитория.

До запуска: выбрать домен и HTTPS, настроить процесс приложения с перезапуском, доступ к PostgreSQL, постоянное хранение загруженных фото, резервное копирование БД и файлов. План обновления должен включать восстановление данных, если миграция несовместима с предыдущей версией.

Предлагаемые проверяемые цели: изменения ХП и боевого состояния видны на других подключённых экранах не позднее секунды после подтверждения сервером при нормальном соединении; сохранённое состояние переживает перезапуск сервера; восстановление из резервной копии проверяется до начала регулярной игры. Целевое число одновременных игроков согласуем отдельно: отсутствие лимита на регистрацию не означает бесконечную нагрузку на одну ВМ.

На этапе этого документа приложение не разрабатывается и не публикуется. Версии библиотек и способ упаковки окружения выбираются перед реализацией.

Виртуальная карта, встроенные кубики, чат/голос, публичная энциклопедия и интеграции с внешними площадками пока не входят в предложенный объём.

## 17. Сценарии приёмки

1. Игрок создаёт двух персонажей и изменяет свои листы; попытка изменить чужой лист или ХП отклоняется сервером.
2. Мастер видит владельцев, редактирует любой лист и управляет справочником.
3. Персонаж входит в две кампании; в одной назначен в отряд, в другой виден в общем пуле.
4. Надевание щита меняет расчёт КД с корректным ограничением; предмет в сумке такого бонуса не даёт.
5. Изменение ключевого слова меняет только подходящие бонусы; неподходящее оружие делает умение недоступным с объяснением.
6. «Благословение» применяется к союзнику и создаёт все три последствия по согласованным срокам и политике ХП; другой клиент видит результат.
7. Физический бросок «Цветного потока» выбирает правильную ветку; отмена и повтор сохраняют именно этот результат.
8. Основное/малое/движение/реакции расходуются по согласованной модели; нельзя восстановить их повторным запросом перехода хода.
9. Эффект «до конца следующего хода источника» заканчивается в нужной точке; стандартный эффект не теряет срок на каждом чужом ходу.
10. Промах `Надёжного` умения, повторное наложение эффекта, нейтрализация и временные ХП обрабатываются по принятым правилам.
11. Мастер меняет ХП; лист и экран показа обновляются без перезагрузки. Игрок не может повторить эту операцию напрямую.
12. Отмена восстанавливает все связанные ресурсы и эффекты без потери более поздних чужих изменений; конфликтующая отмена отклоняется с объяснением.
13. Окончание боя восстанавливает согласованные применения и текущие ХП всех персонажей-участников до максимума, снимает нужные эффекты и сохраняет журнал, общий инвентарь и заметки. Отмена возвращает прежние ХП.
14. Два участника одновременно правят разные фрагменты общей заметки; обе правки сохраняются после перезагрузки.
15. Два игрока одновременно забирают последний общий предмет: успешна только одна передача.
16. Повторное подтверждение умения после обрыва связи не удваивает расход, урон или бонус.
17. Alt/кнопка «Крит» показывает согласованную критическую формулу, отпускание Alt возвращает обычную.
18. Смена версии справочника не переписывает прошлый бой; резервная копия восстанавливает БД и фотографии.
19. Фиксированное лечение и фиксированные временные ХП применяются автоматически; лечение/временные ХП с кубиками и любое списание ХП персонажа выполняет мастер вручную.
20. Применение атаки по монстру учитывает ресурсы умения без обязательного ввода нанесённого урона и без ведения ХП монстра; формула урона и критический вариант доступны игроку.
21. Игрок вступает в кампанию из списка, перемещает своих персонажей между отрядами и общим пулом без согласования мастером; чужих перемещать не может. Переход не восстанавливает ресурсы и ХП.
22. Личные заметки недоступны другому игроку и мастеру через страницу, API и подписки реального времени; общие записи и инвентарь видны в согласованной области общего доступа.
23. Игрок свободно изменяет характеристики, уровень и набор изученных умений своего персонажа без проверки этапа развития. Чужие листы, прямое редактирование ХП и определения общего справочника остаются защищёнными.
24. Модификаторы для значений 9, 10, 13 и 16 равны −1, 0, +1 и +3 соответственно.
25. Владелец ауры выбирает и изменяет её получателей. Добавленный союзник получает бонус, исключённый теряет только вклад этой ауры; листы обновляются в реальном времени. Сайт не определяет расстояния автоматически.
26. При остатке 3 временных ХП начисление 5 даёт итог 5; при остатке 7 начисление 5 оставляет 7. Полное расходование не активирует ранее отклонённые слабые начисления. Конец боя обнуляет остаток; отмена завершения восстанавливает его.
27. Все пять примеров критического урона из раздела 5.1.1 совпадают с расчётом и отображением по Alt.
28. Применение одного умения не расходует запас другого умения того же круга. Небоевое умение недоступно в бою и не имеет расходуемого запаса вне боя.
29. Повторное наложение обновляет срок по ходам цели. При нескольких возможных реакциях выбор получает накладывающий эффект.
30. Лечение от Мод без кубиков не меняет ХП автоматически; фиксированное лечение не превышает максимум, отрицательное значение текущих ХП не сохраняется.
31. Игрок и мастер отменяют каждый своё последнее событие; независимые чужие события сохраняются, чужая история не откатывается автоматически.
32. Участник кампании видит её общие данные независимо от отряда; участник другой кампании без членства доступа не получает.
33. Изменение уровня, в том числе на 3, 5, 7 и 9, не открывает обязательный шаг развития и не меняет характеристики или набор умений автоматически. Игрок вносит нужные изменения самостоятельно.
34. Благословение, наложенное до хода танка, действует во всех трёх его ходах и на реакциях в промежутках. После первого и второго ходов остаётся соответственно 2 и 1 ход; сразу после третьего снимается бонус попадания. Независимый бонус урона до конца боя сохраняется.

## 20. Журнал согласованных решений

12 сентября 2026:

- Учёт отдельных ресурсов действий по книге утверждён.
- Описание умения «Благословение» подтверждено владельцем: «Благословение 2», 5 временных ХП и +1 к урону до конца боя. Первоначальное предположение об отсутствии бонуса к урону было ошибкой чтения эффекта вместо умения и не является требованием. Уточнено: фраза о конце боя относится только к бонусу урона, эффект попадания действует стандартные три хода. Временные ХП действуют до расходования или конца боя по общему правилу.
- Фиксированное лечение и фиксированные временные ХП применяются автоматически; все остальные изменения ХП персонажей мастер вносит вручную, включая урон и лечение/временные ХП с физическим броском.
- Урон по монстрам мастер считает вне приложения; система не ведёт его и не изменяет ХП монстров. Формулы урона умений и критические варианты в листах остаются.
- Игрок самостоятельно вступает в кампании из списка и меняет кампании/отряды своих персонажей.
- Личные заметки видны только владельцу; общие заметки и общий инвентарь видны всем участникам кампании.
- После окончания боя текущие ХП всех персонажей-участников автоматически восстанавливаются до максимума.
- Формула модификатора подтверждена: floor((характеристика − 10) / 2).
- Справочное правило: на 3, 5, 7 и 9 уровнях две разные характеристики получают по +1. Позднейшим решением ограничения по уровням отменены: игрок свободно редактирует характеристики, приложение не выполняет отдельную процедуру повышения.
- Получателей ауры выбирает и меняет игрок — владелец ауры; цели остальных эффектов с выбором указывает владелец источника. Автоматическое определение области и расстояний не требуется.
- Временные ХП действуют до полного расходования или конца боя. При начислении остаётся максимум текущего остатка и нового начисления; суммирования нет. Завершение боя обнуляет временные ХП.
- Школа задаёт характеристику модификатора; классовые умения используют основную школу, оружие — соответствующую оружейную школу.
- Критический набор кубиков рассчитывается по примерам раздела 5.1.1, включая отдельную добавку орка 1Ор.
- Запас применений отдельный у каждого боевого умения. Небоевые запрещены в бою, требуют времени и не расходуются.
- Длительности считаются по ходам цели, повторное наложение обновляет срок. Стихийную реакцию выбирает накладывающий новый эффект.
- Все данные персонажа едины между кампаниями. Противников в очереди нет; мастер начинает бой, игроки завершают свои ходы.
- Игрок и мастер могут отменять только своё последнее действие, каждый по своей истории.
- Регистрация свободная. Мастер может повышать персонажей, игрок — самостоятельно указать уровень своего.
- Текущие ХП не ниже нуля, лечение ограничено максимумом. Лечение и временные ХП от модификатора даже без кубиков не считаются фиксированными: их вносит мастер.
- Эффект действует на протяжении всех положенных ходов цели и промежутков между ними, включая реакции. Снятие — сразу после завершения последнего хода цели; пример для трёх ходов зафиксирован в разделе 8.
- Игрок свободно редактирует характеристики, изученные умения и остальные обычные поля своего листа. Нет обязательного распределения повышений или проверки соответствия развития книге. Общие определения умений редактирует мастер; отдельные ограничения доступа к ХП и чужим листам сохраняются.
